================================================================================
RADIATION DAMAGE ML PIPELINE — OUTPUTS REFERENCE
================================================================================
Project: radiation_damage_ml
Last updated: see git log

This file describes every file and directory produced by the pipeline,
what each quantity means physically, what units are used, and how to
interpret or load the data in downstream training code.

All outputs are written under:
    data/                  — binary/structured data (large, git-ignored)
    outputs/               — human-readable summaries and this file
    logs/                  — runtime logs

================================================================================
STAGE 1 — DATA MINING  (data/raw_structures/)
================================================================================

Source:  Materials Project REST API (mp-api)
Target chemical systems:
    Si               — crystalline silicon, used as a radiation-hard baseline
    Fe-Ni-Cr         — stainless-steel proxy HEA (austenitic steels)
    Mo-Nb-Ta-W       — BCC refractory HEA matching the ADP potential
    Al-Co-Cr-Fe-Ni   — Cantor alloy family
    Ti-Zr-Hf-V-Nb   — HCP/BCC HEA
    W-Mo-Nb-Zr-Ti-Ta — exact composition of WMoNbZrTiTa ADP potential

Files produced per structure:
------------------------------
  <material_id>.cif
      Crystal Information File — open in VESTA, CrystalMaker, or ASE.
      Contains: unit cell vectors, Wyckoff positions, element labels.
      One primitive cell per file (not supercell).

  <material_id>.json
      Metadata dictionary. Fields:
          material_id              — MP identifier, e.g. "mp-13"
          formula                  — reduced formula, e.g. "Fe2Ni"
          chemsys                  — chemical system queried, e.g. "Fe-Ni-Cr"
          nsites                   — number of atoms in the primitive cell
          energy_per_atom          — DFT total energy per atom, eV/atom
                                     (GGA-PBE, VASP, MP r2SCAN where available)
          formation_energy_per_atom— Formation energy relative to elemental refs, eV/atom
                                     Negative = thermodynamically stable compound
          energy_above_hull        — Distance to convex hull in eV/atom.
                                     0.0 = ground state; we keep < 0.1 eV/atom
          cohesive_energy_per_atom — Approximate binding energy (-E_total/atom), eV
          band_gap                 — Electronic band gap, eV (0 = metal)
          density                  — Mass density, g/cm³
          a, b, c                  — Lattice parameters, Å
          alpha, beta, gamma       — Lattice angles, degrees
          volume                   — Primitive cell volume, Å³
          spacegroup_number        — International Tables number (1–230)
          spacegroup_symbol        — Hermann-Mauguin symbol
          crystal_system           — cubic / hexagonal / tetragonal / etc.
          frac_coords              — Fractional atomic coordinates [[x,y,z], ...]
          species                  — Element symbols ["Fe", "Ni", ...]
          lattice_matrix           — 3×3 matrix of lattice vectors, Å

  manifest.json
      Consolidated list of all accepted records (JSON array).
      This is the checkpoint file; Stage 2 reads it.
      Filter criteria applied: energy_above_hull < 0.1 eV/atom, nsites ≤ 80.

================================================================================
STAGE 2 — DEFECT ENGINEERING  (data/defect_structures/)
================================================================================

Each primitive cell from Stage 1 is expanded to a 3×3×3 supercell
(default, configurable in config.py) before inserting defects, to
minimise periodic image interactions.

Defect types generated:
    vacancy      — one atom removed per unique chemical species
    divacancy    — two nearest-neighbour atoms removed (up to 4 pairs)
    interstitial — He or H atom inserted at the largest Voronoi void

For each defect, 3 thermal snapshots are generated by displacing all atoms
with Gaussian noise σ = 0.05 Å (Debye-Waller approximation for finite T).

Defect ID format:  <material_id>__<defect_type>__<NNNN>
    Example:  mp-13__vacancy__0000
              mp-13__divacancy__0003
              mp-13__interstitial__0012

Files produced per defect:
---------------------------
  <defect_id>.xyz
      Extended XYZ format (extXYZ), readable by ASE / OVITO / LAMMPS.
      Contains: cell vectors, atom species, Cartesian coordinates (Å).
      Thermal displacements already applied.

  <defect_id>.json
      Defect metadata. Fields:
          defect_id          — unique string identifier
          base_id            — material_id of the pristine parent structure
          defect_type        — "vacancy" | "divacancy" | "interstitial"
          removed_species    — list of removed element symbols
          removed_position   — Cartesian position(s) of removed atom(s), Å
          inserted_species   — list of inserted element symbols (interstitial)
          inserted_position  — Cartesian position of inserted atom, Å
          n_vacancies        — number of vacancies (0, 1, or 2)
          n_interstitials    — number of interstitial atoms (0 or 1)
          n_atoms            — total atom count in the defect supercell
          cell               — 3×3 supercell matrix, Å
          species            — element symbols of all atoms after defect
          thermal_snapshot   — true (all written structures have this applied)
          thermal_sigma      — RMS displacement amplitude, Å (default 0.05)

  defect_manifest.json
      Ordered list of all defect_id strings. Stage 3 checkpoint.

================================================================================
STAGE 3 — ENERGY / FORCE EVALUATION  (data/evaluated/)
================================================================================

Two calculation backends are used, selected by defect complexity:
    n_vacancies ≤ 2  →  LAMMPS + ADP potential (fast classical path)
    n_vacancies  > 2  →  MLIP: MACE / GRACE / SevenNet (near-DFT path)

ADP potential used:
    WMoNbZrTiTa.nist.adp.txt
    Species order in pair_coeff: W Mo Nb Zr Ti Ta
    Source: NIST Interatomic Potentials Repository
    Accuracy: ~meV/atom for this HEA family (comparable to EAM for metals)

MLIP backends (for complex defects):
    mace    — MACE-MP-0 universal potential.  Auto-downloads medium checkpoint.
              Accuracy: ~15 meV/atom MAE on most metals.
    grace   — GRACE (Graph Atomic Cluster Expansion, ICAMS/RUB).
              Requires manual checkpoint download. Near-DFT accuracy.
    sevennet— SevenNet-0 universal MLIP.  Comparable to MACE-MP.

Files produced per defect:
---------------------------
  <defect_id>.npz
      NumPy compressed archive. Arrays:
          positions      — float32, shape (N, 3), Cartesian coordinates, Å
          forces         — float32, shape (N, 3), per-atom forces, eV/Å
                           Sign convention: F_i = -dE/dr_i (ASE default)
          stress         — float32, shape (6,), Voigt stress tensor, eV/Å³
                           Order: xx, yy, zz, yz, xz, xy
          atomic_numbers — int32,   shape (N,), atomic numbers Z
          cell           — float32, shape (3, 3), supercell matrix, Å

  <defect_id>.json
      Scalar results:
          total_energy_eV        — total system energy, eV
          energy_per_atom_eV     — total_energy / N_atoms, eV/atom
          formation_energy_eV    — point defect formation energy, eV
                                   E_f = E_defect - E_pristine + Σ μ_i
                                   Positive → endothermic defect creation
                                   Negative → spontaneous formation (rare)
          max_force_eV_A         — max ||F_i|| across atoms, eV/Å
                                   Values > 1 eV/Å indicate unconverged geometry
          rms_force_eV_A         — root-mean-square force, eV/Å
          backend                — "lammps_adp" | "mlip_mace" | "mlip_grace" etc.
          n_atoms                — atom count
          defect_type, n_vacancies, n_interstitials, thermal_sigma — from Stage 2

  eval_manifest.json
      JSON array of all result dicts (one per evaluated structure).
      Stage 4 checkpoint.

================================================================================
STAGE 4 — GRAPH TRANSFORMATION  (data/graphs/)
================================================================================

Each evaluated defect structure is converted to a torch_geometric.data.Data
graph for GNN training.

Graph structure:
    Nodes:  one node per atom
    Edges:  one directed edge per atom pair within cutoff radius (6.0 Å, PBC-aware)
            Edges are bidirectional (both i→j and j→i included)

Node feature tensor  x  — shape (N, 5), float32:
    Column 0: atomic_number / 118          (Z ∈ [1, 118])
    Column 1: Voronoi site volume / 50     (typical range 5–50 Å³)
    Column 2: Pauling electronegativity / 4 (range 0–4)
    Column 3: covalent radius / 3          (Å, range 0.3–3 Å)
    Column 4: is_defect_site               (1.0 if within 3 Å of defect, else 0.0)

All columns normalised to approximately [0, 1] for training stability.

Edge feature tensor  edge_attr  — shape (E, 4), float32:
    Column 0:   interatomic distance r_ij, Å (not normalised)
    Columns 1–3: unit displacement vector (r_j - r_i) / |r_j - r_i|

Target tensors:
    y                — total system energy, eV, shape (1,)
    forces           — per-atom forces, eV/Å, shape (N, 3)
    formation_energy — point defect formation energy, eV, shape (1,)
                       NaN if pristine reference not available

Additional per-graph metadata (Python scalars, not tensors):
    z          — atomic numbers tensor, shape (N,)
    pos        — Cartesian positions, shape (N, 3), Å
    cell       — supercell matrix, shape (3, 3), Å
    defect_id  — string identifier
    defect_type, n_vacancies, backend — from earlier stages

Files produced:
---------------
  graphs_raw.pkl
      Python pickle of a List[torch_geometric.data.Data].
      Load with:  graphs = pickle.load(open("data/graphs/graphs_raw.pkl", "rb"))
      Stage 5 checkpoint.

================================================================================
STAGE 5 — CLOUD STORAGE  (data/)
================================================================================

The graph list from Stage 4 is serialised into one or more binary formats
optimised for different training infrastructure.

dataset.lmdb          (LMDB backend)
    Key-value store.  Each graph stored under key b"graph_{idx:08d}".
    b"metadata" key holds a JSON dict with n_graphs, feature dims, cutoff.
    Best for: single-node DDP, NFS/network storage, random access.
    Load: LMDBGraphDataset in stage06_dataloader.py

dataset.h5            (HDF5 backend)
    Chunked, LZF-compressed arrays.  Layout:
        /graphs/{positions, node_feats, atomic_nums, forces, energy,
                 formation_e, n_nodes}   — padded to max_nodes per batch
        /edges/{src, dst, attr, offsets} — CSR-style flat + offset arrays
        /metadata/                       — dataset-level attributes
    Best for: sequential reads, Lustre/GPFS cluster file systems.
    Load: HDF5GraphDataset in stage06_dataloader.py

data/shards/          (WebDataset backend)
    Sharded .tar files (1000 graphs/shard default).
    Each sample: {key}.graph.pkl + {key}.meta.json
    Compatible with WebDataset streaming API and multi-node DDP.
    Best for: streaming from S3 / GCS / Azure Blob storage.
    Load: get_webdataset_loader() in stage06_dataloader.py

data/graphs/splits.json
    Random 80/10/10 train/val/test split indices (reproducible seed=42).
    Format: {"train": [idx, ...], "val": [idx, ...], "test": [idx, ...]}

================================================================================
HOW TO USE OUTPUTS IN A TRAINING SCRIPT
================================================================================

from pipeline.stage06_dataloader import get_loaders
import torch

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

train_loader, val_loader, test_loader = get_loaders(backend="lmdb")

for batch in train_loader:
    batch = batch.to(device)

    # Inputs
    node_feats = batch.x           # (N_total, 5)   node features
    atomic_Z   = batch.z           # (N_total,)     atomic numbers
    positions  = batch.pos         # (N_total, 3)   Cartesian coords, Å
    edge_idx   = batch.edge_index  # (2, E_total)   directed edges
    edge_feats = batch.edge_attr   # (E_total, 4)   [dist, dx, dy, dz]
    graph_idx  = batch.batch       # (N_total,)     maps each atom to its graph

    # Targets
    energies   = batch.y                  # (B,)           total energy, eV
    forces     = batch.forces             # (N_total, 3)   forces, eV/Å
    form_e     = batch.formation_energy   # (B,)           formation E, eV

    # Typical loss: energy MAE + force MSE
    # loss = mae(pred_energy, energies) + 0.1 * mse(pred_forces, forces)

================================================================================
KNOWN LIMITATIONS
================================================================================

1. Pristine reference energies come from DFT (Materials Project GGA-PBE),
   while defect energies come from ADP or MLIP.  Formation energies that
   mix these two levels of theory carry a systematic error of ~0.1–0.5 eV
   depending on the system.  For quantitative E_f, use MLIP for both
   pristine and defect, or use full DFT.

2. The ADP potential (WMoNbZrTiTa) is fit for the specific 6-element alloy.
   If chemsys_queries include elements outside {W, Mo, Nb, Zr, Ti, Ta},
   LAMMPS will fail.  Either extend the ADP or route those structures to
   the MLIP path via a lower mlip_complexity_threshold.

3. Voronoi volume computation (Stage 4) can be slow for supercells >500 atoms.
   If speed is critical, disable it and replace with a fixed value or
   a faster neighbour-count proxy.

4. HDF5 dataset pads all graphs to the max_nodes in the dataset (ragged arrays).
   For highly polydisperse datasets this wastes memory.  Use LMDB instead.
